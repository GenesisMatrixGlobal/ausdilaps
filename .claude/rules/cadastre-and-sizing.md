# Cadastre, address verification + Bulk Property Sizing (PSZ)

Moved verbatim from the root `CLAUDE.md` §3 on 2026-10-26 so it loads only when working on these files. Project-wide rules (Supabase refs, local dev writes to production, guardrails) stay in the root file.

- **Per-lot street addresses (BUILT).** `lib/kml/standard-markup/parcels/addresses.ts` — every state publishes an address layer on the SAME free, keyless ArcGIS service the parcel adapters already use, so this costs no key and no Google quota. QLD joins on `lotplan` (attribute, one call for every lot); NSW and VIC have no lot id so they join spatially against the rings.
  - ⚠️ **This module must NEVER throw.** The parcel adapters throw on failure and should — without a boundary there is no markup. An address is a convenience: a failed lookup returns an empty map, the cells come up blank and the operator types them.
  - ⚠️ **NSW needs `where=principaladdresstype=1`.** Without it one suburban block returns 189 rows (every unit of every strata block) instead of 5 properties. And an envelope given only TWO coordinates is silently accepted and answered with arbitrary features from elsewhere in the state — always emit four.
  - **VIC: use `ezi_address` whole**, never reassembled — `road_type` is null for some roads and `house_number_1` is an integer, so it drops the `A` in "91A". `is_primary` is "Y" on unit rows too, so dedupe by `property_pfi`.
  - ⚠️ **One QLD lotplan can hold FOUR addresses** and not only for strata: 15RP815277 at Aspley is a corner lot addressed off Maundrell Tce, Riordan St, Albany Creek Rd and Gympie Rd, with no primary flag. The pick is deterministic (prefer the subject's street) and the alternatives are surfaced as a markup flag rather than hidden.
- **Bulk Property Sizing (`property-sizing`, code `PSZ`) — the text tab is fed from EXCEL.** `lib/property-sizing/parse.ts` is column-aware: a row's cells arrive tab-separated (or as runs of 2+ spaces from a formula-built sheet). `npm run check:parse` is the regression suite — pure, no env — built from the real Vaucluse / Dover Heights job that broke it (2026-09-10).
  - ⚠️ **A leading cell is a REF only when the address after it still starts with its own street number.** The old `ID<tab>ADDRESS` rule took `11 | CRAIG AVE | VAUCLUSE NSW 2030` as ref "11" + street "CRAIG AVE", and Google, asked for a street with no number, pinned a No. 41 for a No. 42 — then the cadastre returned a convincing lot size for the neighbour. Number-only cells (`42`, `51-53`, `U 1`, `1/48`) are folded into the following cell instead.
  - ⚠️ **No state anywhere and a bare postcode as the LAST cell (`59 Bells of Line Rd` | `north richmond` | `2754`): the suburb is the cell BEFORE the postcode.** The no-state branch took the last cell as the suburb cell, so "north richmond" was glued onto the street and every row of a 34-address North Richmond job hit the sheet with Suburb blank (2026-09-14). Fixed in `parseAddressCells`; two rows of that job are in `check:parse`.
  - **Two-word suburbs:** the cell carrying the state is the suburb cell; a single-cell line with no comma ends the street at the first unambiguous street TYPE (`AVE`, `ST`, `RD`, …) that has a name word before it, so `12 St Georges Tce Perth` and `10 Station St Park Ridge` both split right. The type list deliberately omits HILL / PARK / RIDGE / LAKE / GREEN / HEIGHTS / POINT — valid types, but they appear inside names and suburbs far more often than they end a street. No type found → last word is the suburb, as before.
  - **`houseNumberMismatch()` (`lib/property-sizing/index.ts`) downgrades a row to `status: "number_mismatch"`** when the geocoder's matched address opens with a different number from the one typed (a range accepts either end; a unit prefix is skipped; no leading number on either side = nothing to compare, left alone). The lot size stays visible but the row is orange and counted under "need a manual check" — a wrong parcel that LOOKS resolved is the failure this whole tool exists to avoid.
  - ⚠️ **Paste: TEXT WINS.** Excel puts a bitmap of the copied cells on the clipboard beside the text, and the `window` paste handler used to take the first `image/*` item — so pasting a column of addresses switched to the screenshot tab and OCR'd a picture of the cells. Now any non-empty `text/plain` is text (into the textarea → default browser paste; anywhere else → routed to the text tab), and only a clipboard with no text is a screenshot.
  - ⚠️ **NSW `lotPlan` is `lotidstring` (`61//DP837`), never `planlabel` (`DP837`).** The plan label is the whole deposited plan, shared by every lot subdivided under it, and `sizeProperties()` keys strata detection AND the building-attribute grouping on `lotPlan` — so four separate houses on Eastern Ave read as one strata parcel, were flagged "don't double-count land" and handed a per-unit floor-area estimate. A strata plan's own id arrives as `//SP6635`; the leading slashes are trimmed for display.
- ⚠️ **Google's geocoder puts DIFFERENT house numbers on ONE parcel, and it happens a lot.** Vaucluse / Dover Heights, 2026-09-10: of six addresses, FOUR were on the wrong lot — 44 Eastern Ave on 42's, 12 and 13 Craig Ave on one lot, 45 Eastern on 134 instead of 136 — every one typed `street_address` / ROOFTOP, so the precision gate in `google-geocode.ts` passed them and Bulk Property Sizing reported the neighbour's lot size. `houseNumberMismatch` cannot see it: Google's formatted address still says 44. **Every per-address lookup is now verified against the state ADDRESS LAYER** (`lib/kml/standard-markup/parcels/verify-address.ts`, wired into `lookupLot` in `lib/property-sizing/index.ts`, so Bulk Property Sizing AND the multi-property markup both get it): find the requested number + road by TEXT among the address features within 200 m of the geocode (`address-features.ts` — the same free, keyless ArcGIS layers `addresses.ts` reads, read the other way round; `address-match.ts` is the pure matcher, `npm run check:address`), and if the layer's point is on a different parcel, `parcelAtPoint` there REPLACES the geocoded one (lot/plan, area from `ringAreaSqm`, ring, point) with a flag saying what was corrected. Never throws — anything uncertain leaves the geocode in place with an "unverified" flag. One extra free call per address, one more on a correction.
  - ⚠️ **NSW's address layer is PROPERTY POLYGONS: use `ringAnchor`, never the centroid.** 11 Craig Ave is a 713 m² lot whose polygon is concave; its centroid lands in the neighbour's lot 25, its anchor in its own lot 26. With the centroid the "correction" moved 11 onto 12's lot. And "agreement" is tested both ways — the layer's point inside the parcel, OR the parcel's anchor inside the property polygon — because an NSW property can span several lots.
  - The multi-property markup flags two addresses that STILL share a lot after verification ("… are on the same lot — one outline, pins stacked"): that is now either a genuine strata pair or a layer miss, and the second pin is invisible under the first.
- **`lib/arcgis.ts` — a failed ArcGIS query arrives as HTTP 200 with `{"error":{...}}` and no `features` key.** Every reader here used to do `body.features ?? []` and read an outage as "there is nothing here", so the cadastre tools told the operator *"no titled parcel at this address — measure manually"* and blamed the address. Load-bearing queries now throw; the address enrichment logs and degrades. Bulk Property Sizing told the same lie and is fixed the same way.
- ⚠️ **VIC's parcel cadastre has a fallback, and it is there because it FAILED in production** (2026-09-08, mid-session). `Vicmap_Parcel` began rejecting every spatial query that returns records — "Cannot perform query. Invalid query parameters.", while `returnCountOnly` kept working — and its feature count dropped to 120,400, about 3% of the state, with `parcel_lga_code='HOBSONS BAY'` and `='MELBOURNE'` both counting ZERO. So a fixed query would still have found nothing. `parcels/vic.ts` tries the parcel layer FIRST every time and falls through to `Vicmap_Property` (4.19M features, untouched throughout), so it returns to true cadastral parcels the moment VIC restores the layer, with no switch to flip.
  - The cost: a property PFI is not a title reference, so lot/plan is blank while the fallback is in use — `parcels/parcel-id.ts` is the single place that decides whether an id may be shown as a lot/plan — and `resolve.ts` flags it on the markup.
  - ⚠️ **Property views must be deduplicated by outline.** A strata development has one property row per tenancy, each carrying the WHOLE parcel outline: the shopping centre beside 88 Kingsway, Glen Waverley arrived as 13 identical 10,464 m² polygons and would have eaten 13 numbered pins.
