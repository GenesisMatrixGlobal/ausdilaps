# Quote Line Item sheet + Salesforce line-item sync

Moved verbatim from the root `CLAUDE.md` §3 on 2026-10-26 so it loads only when working on these files. Project-wide rules (Supabase refs, local dev writes to production, guardrails) stay in the root file.

- **Quote Line Item sheet — ONE shared component, hosted by Building Markup AND Bulk Property Sizing (2026-09-10).** `components/tools/shared/quote-lines/line-items-table.tsx` renders it; `lib/markup-layers/` holds the model. A tool turns what it has into `LineItemSource[]` (`lib/markup-layers/source.ts`) via an adapter — `sources/from-layers.ts` for a markup, `sources/from-sizing.ts` for sizing results — and everything downstream (`defaultDraft`, `rowsFrom`, the table, the Salesforce payload) knows only that type. **Change the sheet once and both tools change.** The only per-tool thing is `leading: LeadingColumn[]` — the columns between the item number and Street (markup: swatch + label + measured; sizing: Lot size / Levels / Dwelling). State transitions live in `lib/markup-layers/drafts.ts` (`applyCell` clears the asset-type override when the product changes; `toggleDeselected`), so each tool's handlers are one line. `npm run check:lines` (pure) asserts the picklists, both adapters and the payload; `npm run dry-run:lines -- --sample | <markup>.json | --sizing <results>.json` prints the sheet AND the QuoteLineItem records it would send.
  - **Street View on the DEV tab: ONE listed address → aimed at that property (the red lot if it brought neighbours, else the only lot); more than one → greyed out.** There is no subject in multi mode, so `sitePoint` is derived from the address block's line count, not from `subjectLayer`. The link label is the lot's own street.
  - **No "Layer" column any more (2026-09-11).** The colour swatch sits in the `#` cell beside the item number (any source with a `swatch`), and the lot's address and area are in the sidebar list — the column repeated both. `leading` is `[]` for the markup; Bulk Property Sizing still passes its Lot size / Dwelling columns. **Editable cells carry a faint dashed underline** (`SHEET_INPUT` in `styles.ts`), solid steel on focus — bare transparent inputs read as static text and nobody realised the sheet was editable.
  - **The markup map's zoom needs ⌘ / Ctrl + scroll** (`gestureHandling: "cooperative"` in `markup-map.tsx`; Google picks the key per platform and shows the hint itself). It was `greedy`, and swallowed every scroll meant for the sheet below. Drag-to-pan and the zoom buttons are unaffected. The Measure tab's map is unchanged.
  - **Picklists are the org's REAL ones** (`salesforce-picklists.ts`, from Rhys): `SHEET_PRODUCTS` = the 10 per-property products with their `Product2Id` and the asset type each FORCES (Warehouse → "Standard Internal - Low Density" is inferred from that asset type's API name being `Warehouse` — confirm on the first sync); `ASSET_TYPES` = the 9 `Property_Type__c` values with label AND API value. Drafts and the save file store the product NAME and asset-type LABEL, as before, so every saved markup still opens; ids/API values are looked up at sync time. The 10 per-job products (Mobilisation, DOA, Drone…) are NOT offered — a saved draft naming one still shows, and the sync refuses that row with the reason.
  - **Rates are PICKLISTS in the org, and the option lists are copied VERBATIM from a describe (2026-09-11)** into `RATE_OPTIONS` in `salesforce-picklists.ts` — `Internal_Rate_PL__c` (0.20–0.50 by 5c, 0.60–1.50 by 10c; ⚠ the 0.60 option's API value is `0.6`, every other one is two-decimal) and `External_Rate_PL__c` (0.10–0.80 by 5c; ⚠ API values have NO leading zero: `.30`). The sheet shows/stores the label ("0.80"); `rateToPicklistValue(kind, rate)` returns the API value or `undefined`, and the payload REFUSES a row whose rate isn't an option rather than sending a value Salesforce rejects for the whole batch. The currency twins (`Internal_M2_Rate__c`, `External_Rate__c`) are written too — the team's real lines carry both. Don't derive these lists; copy the org.
  - **Describe facts (2026-09-11, run as rhys@):** required on create = `QuoteId, PricebookEntryId, Quantity, Product2Id`; `UnitPrice` nullable (we send 1); `Levels__c` is `double(7,1)` "Levels / Lanes" (a `Levels_PL__c` 1–15 picklist also exists and is NOT written); `Property_Type__c` API values match `ASSET_TYPES` exactly; all 10 sheet products have ACTIVE entries on the **Standard Price Book** (`01s6F000007EzsAQAS`, the only active book — "AusDilaps Price Book" and "Test" are inactive); every field the sync writes reports `createable=true` for the run-as user, and the user has Create on Quote (QuoteLineItem has no ObjectPermissions row of its own — it follows Quote). The describe is `scratchpad/sf-describe.ts`-style read-only SOQL; re-run it after any picklist change in the org.
  - ⚠️ **`.env.local` `SF_LOGIN_URL` MUST be `https://ausdilaps.my.salesforce.com`.** It sat at `login.salesforce.com` (the example file's placeholder) and the token call failed with `invalid_grant: request not supported on this domain` — exactly as `docs/salesforce-markup-sync.md` warns. The key and secret were fine.
  - ✅ **The line-item create WORKS against the org (first run 2026-09-11):** three QuoteLineItems created on scratch Quote 00005267 (`0Q0Ol000004I47hKAC`, test Opportunity `006Ol00000A6npuIAB`) — two via the code path, one through the Bulk Property Sizing footer in the browser. Product, PricebookEntry, Quantity, `UnitPrice 1`, `Levels__c`, m², both rate picklists and their currency twins all read back exactly as sent; Salesforce filled `Description` itself. ⚠️ **The org's active before-save flow `QLI | Master Pre-fill (On Create)` (`QLI_Property_Type_Product_On_Create`) OVERWRITES `Property_Type__c` from the product on every insert** — a Residential House line sent as `Commercial` read back `Commercial_Dense`. Until that flow is changed to fill only when blank, the sheet's Asset type cell is advisory on create. Also active on QLI: `QLI | Update Address & Quote Description` (fills Description/Street/Suburb), `QLI | Check 'Mobilisation'`, `Quote | Mobilisation Notes When QLI Added`, the CHC OLI sync. Unsent fields take the org's defaults (`External_Rate_PL__c ".30"`, `External_Rate__c 0.25`, `Internal_Rate_PL__c "0.80"`, `Levels__c 1`).
  - ⚠️ **On the markup tabs, line items are created AFTER the PNG upload, so the panel needs a Box folder** (the Opportunity's `Link_to_Box_Files__c`, or a pasted folder link). A job with no Box folder can't create lines from the markup yet — Bulk Property Sizing's footer has no such dependency. A "create line items without the image" option is the obvious follow-up.
  - **Sync to Salesforce (line items) — design notes** — `lib/quote-lines/{payload,resolve}.ts`, `/api/salesforce/quote-lines/{resolve,create}`, footer `sync-quote-lines.tsx` inside the shared table. Rules agreed with Rhys: **one QuoteLineItem per row** (both m² fields on one line), **`UnitPrice = 1`** as a deliberate placeholder so pricing is finalised in Salesforce, **no `Description`** (the org fills it), `Quantity` = Qty, `Property_Type__c` = asset type API value, `Internal_M2__c`/`Internal_M2_Rate__c`/`External_M2__c`/`External_Rate__c`/`External_Rate_PL__c` sent only with a non-zero measurement. `createRecords()` (`lib/salesforce.ts`) uses the Composite sObject Collections endpoint with `allOrNone` — one token, atomic — and checks the per-record `success` flags, because Salesforce returns 200 for a rolled-back batch. The server re-resolves the Quote's price book and rebuilds every record from row VALUES; it never trusts a client `PricebookEntryId`. **Any refused row = 400 with `refused[]` and nothing created.** No server-side dedupe: the footer warns "already has N line items" and locks Create after success until a ticked row changes. First real create: a scratch Quote on the testing Opportunity `006Ol00000A6npuIAB`; the run-as user has never created a QuoteLineItem through the API, so `INSUFFICIENT_ACCESS` there is a profile fix, not code.
  - **"Clear the Quote first" — REPLACE instead of add (2026-09-16).** Rhys asked for it because a re-priced job synced twice leaves two of everything, and there is no server-side dedupe. A checkbox on BOTH sync surfaces (the markup toolbar panel and the sheet footer), **OFF by default and re-set after every run** — deleting someone's line items is never a thing to do by momentum. `lib/quote-lines/clear.ts` → `POST /api/salesforce/quote-lines/clear`: deletes every QuoteLineItem on the Quote (batched at 200, looped) and blanks all five `Site_Mark_Up_N__c` URL slots **and their `_Name__c` companions** (a name left behind with no URL reads as a failed upload). Four things make it safe enough to offer: the route takes a **Quote ID only, never free text**, so it can only hit a Quote the operator already resolved and saw on screen; the client only enables the button when every ticked row is sendable, so the usual failure can't leave a Quote emptied; **the BOX FILES ARE NOT TOUCHED** (only the Quote's links to them — and the service account is Viewer, so it couldn't delete them anyway); and the counts in the label come from the resolve, while the counts in the RESULT are measured server-side by the clear itself. ⚠️ **Never offered for a pasted LINE ITEM** (`!target.lineItem`) — clearing the Quote would delete the very record the drawing is being attached to. On the markup panel the clear runs **BEFORE the upload**, so the new PNG lands in Site Mark Up 1 rather than after links that are about to go; ticking it also re-enables linking on a Quote whose five slots were full, and the slot label says "(the slots are being cleared)". Both resolvers gained the counts the label needs: `existingLines` on `resolveQuoteTarget`, `markupSlotsUsed` on `resolveQuoteForLines`. Verified end to end against the scratch Quote: 9 lines + 2 slots → `{deletedLines: 9, clearedMarkupSlots: 2}` → 0 and 0, a second run a harmless no-op, and through the sizing footer "Cleared 3 line items and 1 markup link, then created 2 line items".
  - **A "Ready To Send" Quote is put back to DRAFT before line items are written (2026-09-21, Rhys).** `lib/quote-lines/editable.ts` → `ensureQuoteEditable()`, called by BOTH the create and the clear routes (the lock blocks deletes too). ⚠️ **The error it prevents does not name the real cause.** Creating a QLI on a locked Quote fails with `FIELD_CUSTOM_VALIDATION_EXCEPTION: Status cannot be 'Ready To Send' because 1 or more Quote Line Items still contain 'XXX'` — which reads as a complaint about the OLD lines. It isn't: the org's after-insert flows re-save the Quote, its status rules run again, and the line just added has no Description yet. The rule that WOULD have said it plainly (`Quote_Not_In_Draft_Status` on QuoteLineItem, "Your Quote Status needs to be changed to Draft in order to make changes") is **INACTIVE** in the org, so don't go looking for it. The org's own message says to do exactly this: *"If you are adding a new Line Item, please make sure the Status is 'Draft'."*
    - ⚠️ **It is NOT locked again afterwards, deliberately.** A Quote that just gained a line item cannot return to Ready To Send until someone fills that line's templated text and markup — those are the same active rules (`Cannot_Update_Status_if_XXX_in_QLI`, `Cannot_Update_Status_If_Blank_QLI_Markup`, `Cannot_Update_Status_If_No_Markup_Folder`). Flipping back would fail, and succeeding would mark an unchecked quote sendable. Both UIs say so before AND after.
    - ⚠️ **Only ever flips from `"Ready To Send"`.** Draft and Ready To Send are the ONLY two ACTIVE picklist values (describe, 2026-09-21; 4,270 Ready To Send / 508 Draft / 8 legacy "Sent"). "Sent" is inactive, so it could never be set back once overwritten — leaving it and letting the error surface is the safer failure.
    - The flip runs **after** payload validation and **before** `createRecords`, so a refused row never unlocks a Quote for nothing. Both resolvers report `status` so the panel warns before anything is written; the result says what it changed. Verified live: locked scratch Quote → resolve reports "Ready To Send" → unlock → 2 lines created → status Draft → a second call is a no-op.
  - **Sizing rows**: product Residential House (Residential Unit for a unit), **dwelling-area estimate → Internal m²**, **storey estimate → Levels**, external blank; a row with `status !== "ok"` starts UNTICKED and orange. Building Markup's rows are unchanged: colour → product and column, orange street "Council assets", red seeds no measurement and no levels.
  - **Levels column → `QuoteLineItem.Levels__c`** (integer, sent only when > 0). **Defaults to 1** (a markup lot or red/blue shape) or the storey estimate (sizing); **an ORANGE shape — council assets — seeds BLANK and sends nothing**, and a blank cell is not highlighted (nothing to check). **The cell is ORANGE until the operator has touched it** — clicking is enough — because a seeded storey count must be looked at before it goes on a Quote. **And NO sync runs while a ticked row is still orange**: `levelsUnchecked(row)` in `line-items.ts` is the one rule, used for the highlight, the sheet footer's Create button and the markup panel's Upload button (when line items are wanted), each saying how many cells are left. A blank cell (council assets) is never flagged. "Touched" = the field is present in the row's sparse draft (`LineItemRow.touched`, from `Object.keys(drafts[key])`); focusing the cell writes the current value back into the draft, which is what clears it, so the state rides in the save file with no separate flag. In the save-file whitelist and the create route's zod (defaulted). The sizing tool's own "Levels" leading column went — the estimate + confidence sits in the lot-size sub-line.
  - **`Street__c` / `Suburb__c`** (string(100) each) are written from the sheet's Street and Suburb cells (2026-09-11). `lib/salesforce.ts` also has `deleteRecords()` now — the composite all-or-nothing undo for `createRecords`, used to clear the test lines off the scratch Quote.
  - **Where the sync lives differs by host, deliberately.** In the markup tabs the toolbar's **Sync To Salesforce** panel does BOTH jobs from one pasted Quote: file the PNG, then create one QuoteLineItem per ticked row (`lineItems={{ rows }}` on `SyncToSalesforce`; checkbox on by default, blocked rows listed and the button disabled until fixed or unticked; a line-item failure is reported beside the upload result, never as a reason to re-upload). The sheet's own footer (`sync` prop) is OFF there — two paste boxes for one Quote on one page was the confusion. Bulk Property Sizing has no image, so it keeps the footer.
  - Cells are held as STRINGS, the way a spreadsheet holds them, and parsed on read (`parseCell`). **The item number is display-only** (`rowsFrom` counts ticked rows); nothing joins on it. `assetType` was missing from the save-file whitelist (`LINE_ITEM_FIELDS` in `building-markup-file.ts`) until 2026-09-10, so overrides vanished on reopen — fixed.
