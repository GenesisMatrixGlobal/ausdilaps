# Samples page, access gate + visitors

Moved verbatim from the root `CLAUDE.md` §3 on 2026-10-26 so it loads only when working on these files. Project-wide rules (Supabase refs, local dev writes to production, guardrails) stay in the root file.

- **Samples page (RESOLVED — was the pre-cutover blocker):** `/dilapidation-reports/samples` renders from Box, and the static `FALLBACK_CATEGORIES` list that linked LIVE WordPress PDFs has been **deleted** — post-cutover `ausdilaps.com.au/wp-content/...` resolves to this site, so those 19 links would have 404'd. Box is now the only source and the page 404s if it can't be read; ISR keeps serving the last good render, so a Box blip never reaches a visitor, and `lib/box.ts` uses `Promise.allSettled` throughout so one bad file or subfolder can't take the page down. See `docs/box-samples-sync.md`. **Redesigned as a LIBRARY 2026-09-11** (`components/marketing/samples-library.tsx` + pure `lib/samples.ts`): a SLIM header (breadcrumbs, h1, one contact line — no PageHero, no eyebrow, no intro paragraph; Rhys: "KISS") then category chips over a COMPACT LIST (one row per file: icon, title, type · size · year) — a search box and a 3-column card grid were tried and dropped the same day on Rhys's request (too many screens), category order fixed in `CATEGORY_ORDER` (Box sorts A–Z and put Case Studies first), titles parsed from filenames with the "AusDilaps Sample 2026 -" boilerplate stripped. **No "Request a Quote" on the page itself** — people looking at samples usually already hold a quote (Rhys) — just phone + email; the site header keeps its button. Only `pdf/png/jpg/jpeg/mp4/mov` are published (`SAMPLE_EXTENSIONS`), because the page makes every file it lists a PUBLIC download and several people, one external, hold Editor on the folder. The service account is **Viewer** on the samples folder and that is CORRECT — a Viewer can create a shared link (PUT 200, verified 2026-09-11) but cannot delete (403). Rhys asked for least privilege here; don't "upgrade" it to Editor, and don't trust the older comments that said Viewer was insufficient. ✅ `BOX_*` env vars are on Production AND Preview since 2026-09-11. **ACCESS GATE (2026-09-11; the CODE BOX REMOVED 2026-09-30, Rhys — the way in is NAME + EMAIL and it is the only thing on the page).** ⚠️ `gateEnabled()` IS DELETED: it returned `accessCodes().length > 0`, so clearing `SAMPLES_ACCESS_CODE` would now mean "no code configured, let the world in" — the gate is unconditional and the email unlock writes a FIXED token (`unlockCookieValue()` = a hash of `email-unlock`, not of any code), so retiring the code cannot open the library. `?code=` is STILL honoured silently for quote links already sent, and a code that no longer validates lands on `?error=code`, which the form reports as "that link has expired" rather than as the visitor's mistake. Everything below describes the original two-door version: the list is behind a courtesy code — `lib/samples-access.ts` + `samplesGate()` in `proxy.ts`. Two static pages, one URL: `/dilapidation-reports/samples` is the LOCKED teaser Google sees (unlock forms, the Box `Public` subfolder open, other categories as name + count); `/dilapidation-reports/samples/library` is the real list (noindex, robots-disallowed), reached only by middleware REWRITE when the `ad_samples` cookie (SHA-256 of the code, httpOnly, 6 months) is present. Quotes link `/samples?code=XXXX`; the middleware sets the cookie and redirects to the clean URL. Email fallback `POST /api/samples/unlock` writes a `leads` row (`routing='samples-unlock'`), notifies sales, sets the same cookie. `SAMPLES_ACCESS_CODE` is set on Vercel prod+preview and `.env.local` (comma-separate for rotation; **unset = gate OFF, fail open**). ⚠️ Neither samples page may read `cookies()` or `searchParams` — that makes it dynamic and loses the ISR outage protection; the gate lives in the middleware for exactly that reason, and the unlock form reads `?error=` in the browser. **Visits are COUNTED in `samplesGate()`** via `after(() => recordPageView(...))` (`lib/page-views.ts`, table `page_views`, migration `0015`): events `view_locked` / `view_library` / `unlock_code` / `unlock_code_failed`, plus `unlock_email` from the API route; bots, prefetches and headless browsers (our own tests) are filtered by UA and `sec-fetch-dest` BEFORE a row is written. `/admin` shows "Samples viewed · 7d" from it. ⚠️ **`routing = 'samples-unlock'` leads are EXCLUDED from the enquiry counts** on `/admin` (a name + email left to open the library is a warm contact, not an enquiry) and reported on the samples tile instead. See `docs/box-samples-sync.md`.
- **Samples VISITORS (BUILT 2026-09-18, Rhys: click "Samples viewed" and see the people, the dates, and which items they clicked).** `/admin/samples` (the tile's `href`, and a nav link) lists one row per BROWSER over 90 days — name/company when known, how they got in, first/last seen, views, files opened, device, external referrer — opening to the files and full history. Migration **`0021_samples_visitors.sql`** adds `page_views.visitor_id` / `lead_id` / `item` and the event `click_item` — the identity 0015 deliberately left off; its header says why that changed. ⚠️ **NOT YET APPLIED** — until pasted, `recordPageView()` retries in the 0015 shape (so the tile keeps counting) and `/admin/samples` says to run it. **Identity is a cookie, `ad_samples_v`** (random UUID, httpOnly, same options as `ad_samples`), minted by `samplesGate()` on a browser's first COUNTABLE hit — before any unlock, so locked-page views and the eventual unlock join up; bots get none. ⚠️ **A NAME attaches ONLY through the email unlock** (`lead_id` on the `unlock_email` row → `leads.name/email/company`). The access code is ONE code on every quote, so a code unlock is anonymous by construction and is shown as "Visitor 3f9a2c1e · Access code" — never guessed at. The way to identify code unlockers would be a per-quote parameter on the samples link (e.g. `?code=…&ref=OPT-25824`) recorded on the unlock row; not built. **Clicks:** `SampleRow` fires `navigator.sendBeacon` to `/dilapidation-reports/samples/click` (`app/(marketing)/dilapidation-reports/samples/click/route.ts`) — under the samples path, NOT `/api`, because both cookies are scoped to `/dilapidation-reports` and would not reach `/api/*`. Public by necessity, bounded like `/api/vitals`: zod, bot filter, `sec-fetch-site: same-origin`, and BOTH cookies required (the access cookie proves they are unlocked). `item` is stored as "Category · Title". Rows before 0021 have no visitor and are reported as "Untracked views", never dropped. Loader `lib/admin/samples-visitors.ts` pages PostgREST at 1,000 rows, oldest first.
