# Staff games: Site Snap (SNP) + CrackBlast (CRK)

Moved verbatim from the root `CLAUDE.md` §3 on 2026-10-26 so it loads only when working on these files. Project-wide rules (Supabase refs, local dev writes to production, guardrails) stay in the root file.

- **Site Snap (`site-snap`, code `SNP`) — the staff game.** Top-down pixel photo survey: walk the house, photograph all 28 walls (four per room, incl. the backyard fences) from in front of the middle of each one, inside a 90-second clock. Shared leaderboard, migration `0014` (APPLIED to Sydney — an earlier note in this file's history claimed otherwise and was wrong). Replaced a Ping Pong prototype that was never committed and whose table was never created.
  - ⚠️ **The rule was "shoot from the centre of the ROOM" until 2026-09-18 and is now "in front of the middle of the WALL".** Rhys's call, and it is what the job actually is. The old rule gave all four walls of a room ONE stand point, so 28 captures were really 7 decisions and a run was ~93 tiles of walking; it is ~165 now. **The leaderboard was reset with the change** — `site_snap_scores` has no season column, so a mixed board silently compares two different games.
  - **Stand points are DERIVED FROM A CAMERA, not hand-picked** (`STAND_POINTS` in `house.ts`): a `FOV_HALF_ANGLE` (50°, a wide-angle inspection lens) cone is exactly `length` wide at `length/2 / tan(FOV_HALF)`, so the ideal standoff is where the wall fills the frame, clamped into the room by `MIN_STANDOFF` and `STANDOFF_MARGIN`. That is what makes the on-screen cone a READOUT rather than an ornament — the cone's edges landing on the brackets IS the correct spot, with no second set of numbers to learn. ⚠️ Two invariants, both SILENT when broken and both asserted by `check:sitesnap`: `STANDOFF_MARGIN > PLAYER_HALF` (or the mark is unreachable and the bot's settle loop spins out and shoots from where it stalled) and `MIN_STANDOFF <= minRoomDepth - STANDOFF_MARGIN` (or the clamp inverts and returns a standoff outside the room).
  - **ONE definition, three consumers.** `STAND_POINTS` + `positionVerdict()` + `shotPreview()` are read by the engine (which takes the photo), the renderer (which tints the cone and the lit wall slice) and the balance harness (which routes to them). A cone that promised a score the shutter then refused would be worse than no cone; three re-derivations of the clamp is exactly how that happens.
  - ⚠️ **The falloff plateau is ABSOLUTE (±0.8 tiles standoff, ±1.2 lateral), not a fraction of the ideal.** Scaling it evens out the perfect region as a proportion of each room, which is the wrong denominator — what a player feels is how much slop their feet get, and that should not change room to room. It also undoes the change where it matters: proportional takes the living room's north wall from 17% to 63% when shot from the room centre. And a WIDE flat top (±1.5) leaves 18 of the 28 walls scoring a full 100 from the old centre spot — the rule changes and the game doesn't. Forgiving is delivered by the RAMP, not the plateau.
  - ⚠️ **`lateralZero` comes from the FRAME WIDTH (`ideal * FOV_TAN + 1.5`), never the wall's length.** Identical on the 24 walls whose standoff is unclamped, so it is a no-op there. It exists for the hall: 23 tiles long, 3 deep, so on wall length its long walls were shootable from 98% of the corridor — you could photograph the north wall from the far west end at full marks. On frame width it is 31%.
  - ⚠️⚠️ **TWO colours on the cone, and which goes where is the whole readout. This was shipped WRONG IN BOTH DIRECTIONS inside one afternoon (2026-09-18), so don't "simplify" it back.** Tinted entirely by QUALITY (position x focus), a cone that plainly filled the brackets still showed amber while focus rebuilt — Rhys: *"it looks like you've got the full width ready, but it still doesn't go green"*. Tinted entirely by FRAMING, it went green the instant you were in position, you fired, and the wall you walked away from was red — Rhys: *"it goes green and I snap a photo, I walk away, it was actually red because it was low quality"*. **Both complaints are right, because they are about different questions.** So: the cone's **OUTLINE** is `ShotPreview.framing` (position x cat, no focus) and snaps green as soon as you are on the mark; the cone's **FILL and the LIT WALL SLICE** are `ShotPreview.quality` (framing x focus) and ripen red → amber → green as the camera steadies. The lit slice is the load-bearing half: it is drawn over the wall's status strip in the same palette through the same `qualityColour()`, so **it is literally a preview of the colour the wall will keep** — shoot it green and it stays green. `npm run check:sitesnap` pins all three facts. The **focus ring over the player's head was deleted** in the same change: the wall bar is the same gauge, reading out in the place the player is already looking, and two gauges for one shot was half the confusion. The cat sits on the FRAMING side — it is something in the shot, which is exactly what the cone shows.
  - **The viewfinder brackets the TARGET BAND, not the whole wall** (`targetBand()` in `render.ts`). Same reason: no photo from inside a 3-deep hall can hold more than a fifth of a 23-tile wall, and scoring is already relative to what is achievable there — so without this the drawing contradicted the HUD, a short lit bar on a long wall beside a reading of 100%. "Fill the brackets" is now one instruction that holds on every wall in the house.
  - **Two walls are free at spawn, deliberately.** Standing where you start scores 100 on both of the hall's long walls. Kept and asserted: it is the best onboarding the game has — the flash goes off and a wall turns green before the player has moved. **The bathroom is deliberately still a tripod room** (5 wide, ideal standoff 2.52, so its east and west marks land 0.03 tiles apart), also asserted so it cannot drift into being an accident.
  - **The engine is DOM-free** (`engine.ts`) so `npm run check:sitesnap` can drive thousands of runs headlessly. That script is the point: it asserts the house is completable, that the player cannot clip a wall, and — the one that matters — that **the best strategy is neither extreme**. Two earlier designs failed it, both the same way Pong's first build did, by letting a competent player saturate the scoring.
  - ⚠️ **The FOCUS meter is EXPONENTIAL, not linear.** Standing still, the camera steadies with a time constant; quality is `position x focus`. ⚠️ **Position and focus are not interchangeable knobs**: for a player who parks exactly on the mark, the per-wall rule changes quality by NOTHING (the position factor is 1.0 there, exactly as the centre factor was 1.0 at the centre) — its entire balance effect is the extra walking. Position decides WHERE you may shoot from; focus decides WHEN, and only the second is a trade. Linear focus made quality and the clock both linear in time spent, so the trade never peaked and every strategy scored within 4% of the others. Focus is also consumed PER SHOT — with it persisting, one wait covered all four walls of a room and quality outvalued the clock ~12x.
  - ⚠️ **The time bonus pays ONLY on a complete survey.** Without that, the best play is to shoot the easy half of the house and go home. `BONUS_PER_SECOND` is the single balance knob; tune it, not the quality curve, and re-run the check.
  - ⚠️ **The cat and the toddler punish OPPOSITE behaviours, and that is the whole reason both exist.** The cat pathfinds after you and zeroes the focus meter when it reaches your ankles, so standing still — exactly what the focus meter asks for — is never free. The toddler only trips you while you are MOVING (flat on your back for 1.3s, no shooting), so sprinting between rooms is never free either. **One toddler since 2026-09-18** (Rhys), and ⚠️ the spawn ORDER in `newGame` matters because the array is sliced: index 0 is the living room, because the old index 0 was inside bed1 — the first room on the natural route — so the lone toddler was underfoot within seconds of every run and then retreated for the rest of it. Measured separately at the time: dropping the second toddler is worth +80 to a rusher and +35 to a balanced run, and widening the cat's frame (below) costs a perfectionist 54 and a rusher nothing. They pull opposite ways on purpose; change one and re-run the check before changing the other. Neither hazard has a strategy that beats it, so the player has to keep switching. Change one of them to punish the same thing as the other and the middle of the run goes flat again.
  - ⚠️ **A hazard's SPEED and its BACKOFF are coupled — change one and check the other.** Rhys asked for a slower cat and toddler on 2026-09-18 (`CAT_SPEED` 2.9 → 2.2, `TODDLER_SPEED` 1.55 → 1.1). A slower cat that also stayed away as long became cheap enough to simply ignore, and `check:sitesnap` said so immediately: the "ignores the cat" strategy went from losing to WINNING outright. `CAT_BACKOFF` 2.6 → 2.0 is the counterweight — it walks slower and comes back sooner, so total pressure is about what it was. A hazard whose best counter-play is to not think about it is scenery.
  - ⚠️ **Every hazard must BACK OFF after it lands a hit, and must be escapable.** Both retreat across the house for ~2s, and a trip is followed by 1.4s of immunity. Without that a cat can camp a room and a toddler can chain-trip, making the survey uncompletable and the completion bonus unreachable through no fault of the player. Same trap the cat's first "refuse the shot" version fell into — the fix there was that it SPOILS a shot (x0.4) rather than refusing it.
  - Chasers path with a BFS in `house.ts`, re-planned every 0.35s rather than per frame. Homing straight at the player and sliding along walls leaves a cat wedged in a bedroom while the player works two rooms away — a hazard that cannot reach you is scenery.
  - ⚠️ **Do not give a bot "stand still when a toddler is near".** It reads as the obvious counter (trips need a moving player) but it DEADLOCKS — they home on you, so stopping means stopping forever. Every bot given that rule froze in the hallway and scored ~500 against ~3450 for one that walked on and ate the occasional trip. Steering around them is the player's job; the sim does not model it.
  - **The plan is 36x21 tiles with a one-cell margin of lawn, six rooms and a fenced BACKYARD — 28 capture targets, not 24.** The yard is a real target, not scenery: photographing boundary fences and external elevations is a genuine part of a survey, so the run finishing outdoors is the most true-to-life thing in the game. ⚠️ **36 columns is a hard ceiling, not a preference** — the tool column is ~1176px, so a canvas wider than 588 logical px can no longer scale by a whole 2x and drops to 1x. Every column added has to come out of another.
  - ⚠️ **Everything unclaimed by a room is SOLID, which is right for collision and wrong for drawing.** `isStructural()` (adjacent to any room cell) is what separates built wall from open ground; without it the lawn margin renders as cream wall and the house looks embedded in a block rather than sitting on a block of land.
  - **The house is baked ONCE into an offscreen canvas and blitted each frame** (`bakeStatic()`). Floors, walls, windows, props and the yard never change during a run, so re-issuing ~900 fillRects at 60fps to redraw a floor that has not moved was the easiest waste in the file to remove. Only capture status, the field-of-view cone, actors and effects draw live.
  - ⚠️ **The HUD mirror's dirty check gates every readout** (`index.tsx`). The live `This shot %` had to be added to that comparison or React never hears about it; it is quantised to whole percent, which is what stops it being a 60fps re-render.
  - ⚠️ **`catInShot()` uses the SAME cone the renderer draws**, not a fixed half-plane. It was `|sideways| < CAT_FRAME_HALF_WIDTH` unbounded in depth, which was consistent while every wall was 2-3 tiles from a player at the room centre. Shooting the yard's east fence from its 5.45-tile standoff the real frame is 6.5 tiles wide, so a cat sitting plainly inside the drawn cone cost nothing — and with the cone on screen that does not read as a design decision, it reads as a bug.
  - ⚠️ **`check:sitesnap` had FOUR ways to pass while measuring nothing**, all introduced by the per-wall rule and all now closed: it asserted every ROOM CENTRE was reachable (a place nobody stands); its settle and walk loops bailed out silently and shot from wherever they stalled; its retry loop re-fired a refused shot FROM THE SAME SPOT, which can never fix a position refusal and silently zeroes the completion bonus; and `sloppiness` measured nothing and never had (six of seven strategies used offsets inside the perfect radius, so they all scored an identical 1.00). `precision` — the position factor at which the bot stops walking and fires — is the axis the rule actually creates. The script also now asserts the model DISCRIMINATES: 6+ walls refused from the room centre, and no single spot in the hall, living room or yard clearing 0.5 on all four walls. Without those a sign error would leave every balance assertion green.
  - **Routing is room-at-a-time with the four marks inside a room brute-forced over all 24 permutations**, exit leg included, walking straight lines inside a room and BFS only between them. Not fussiness: flat greedy over all 28 points measures 179 tiles against 165, and following BFS cell centres inside a room over-measures the game by 10-15% because the engine normalises a diagonal and a real player cuts the corner. Distances come from one BFS per node at module load, not per iteration.
  - ⚠️ **The shutter flash decays CUBICALLY.** Punch is a high peak that clears fast: the quadratic version held the screen over 50% white for ~0.16s, which across 28 shots spends a real fraction of the run unable to see the house. A refused press fires a short red `dud` pulse instead of nothing at all — without it, pressing space out of position read as an unresponsive control and players pressed harder rather than moving.
  - Walls occupy CELLS here, unlike `lib/floor-plan`, which puts them on grid lines. That turns collision and doorways into a `solid[y][x]` lookup. `buildOwnerGrid` was deliberately NOT reused: it value-imports `./types`, which drags **zod** into this lazily-loaded game chunk, for five lines of loop. Room shapes stay structurally identical to floor-plan's `Rect` so "walk a real plan" stays a small adapter.
  - Canvas scales by **whole multiples only**. Pixel art at a fractional scale is worse with `image-rendering: pixelated`, not better — nearest-neighbour duplicates some source columns and not others, so strokes go uneven and the image shimmers.
  - **Scores get a table PER GAME** (`site_snap_scores`), not one generic `game_runs` keyed by slug. Asked and answered on 2026-09-08: a generic append-only table was proposed — one migration ever, one shared API route and leaderboard, plus full run history for checking the balance against real players — and was declined in favour of per-game typed columns and constraints. So each new game costs its own migration (hand-pasted while the token is expired), its own API route and its own leaderboard. Don't re-propose the merge without a reason that has changed.
  - Sprites are string-array pixel maps baked once into offscreen canvases (`sprites.ts`). `ctx.imageSmoothingEnabled` matters only for those `drawImage` calls — it does nothing for the `fillRect` work that draws the house.

- **CrackBlast (`crack-blast`, code `CRK`) — the second staff game (2026-09-29).** Block puzzle where a finished row/column cracks and shatters. Ported from Rhys's CrackBlast v2.0 design build (a Claude Design "dc" template that loaded React + Babel from unpkg at runtime) into a plain React class in `components/tools/crack-blast/index.tsx`; `rules.ts` is the pure half (shapes, solvable deal, scoring ceilings the API checks), `themes.ts` the nine walls verbatim, `crack-blast.css` the Organic tokens SCOPED to `.cb` (fonts via `next/font`: Caprasimo + Figtree). Deliberate changes from the design: **board fixed at 8x8 and the design-tool settings removed** (one leaderboard needs one game); it is a panel on the tool page with a **full-screen button** (fixed overlay, not the Fullscreen API — iPhone has none); Restart moved into the pause menu to make room for that and a leaderboard button. Leaderboard = `crack_blast_scores` (migration `0026`, Site Snap's shape: best run per person, name from the session, service-role writes), `/api/crack-blast/scores`; a run posts on game over OR on a restart with points. The zod check bounds a score by `moves x 18 + lines x 1,200` — self-reported, like Site Snap.
