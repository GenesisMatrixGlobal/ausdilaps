# Tender Watch (TDW)

Moved verbatim from the root `CLAUDE.md` §3 on 2026-10-26 so it loads only when working on these files. Project-wide rules (Supabase refs, local dev writes to production, guardrails) stay in the root file.

- **Tender Watch (BUILT — don't redo):** the nightly tender pipeline. `/staff/accounts/tools/tender-watch` (also the Command Centre's Tenders tab, `/admin/tenders`; admins get the operator panels via the `isAdmin` flag). See `docs/tender-watch.md`.
  - **Not a scraper.** AU tender portals mostly offer email alerts, not feeds (AusTender's ATM RSS is the exception; tenders.gov.au and data.gov.au both 403 automated fetches). `tenders@` registers for every portal's alerts and the portals become the crawler. Two adapters, both built: `rss` (code-owned URLs, for SSRF reasons) and `email` (MS Graph, app-only).
  - **Email sources are DISCOVERED, not listed.** Every sender domain in the mailbox gets its own `tender_sources` row on the first night it emails — slug `email:<domain>`, no code change, no migration. `discoverMailboxSources()` runs before the source list is built, because a domain with no row would otherwise never be fetched.
  - ⚠️ **`alert_on_quiet` defaults FALSE and must stay that way.** Every direct client invitation is also a source, and `summary.ts` marks anything `critical` after 5 empty runs — alarms-on-by-default would paint the dashboard red inside a month and bury the portal that actually stopped sending. Failures are never opt-in.
  - **Parse-mode `auto` leans digest on purpose.** A 30-tender digest read as one email loses 29 silently; a single read as a digest just makes junk the classifier rejects. The zero-link fallback in `parseDigest()` is what makes that bias safe — don't remove it.
  - `npm run check:tenders` (pure, no env) and `npm run check:sources` (writes throwaway rows to the real DB).
  - Vercel Cron at `0 19 * * *` UTC = **5am Brisbane year-round** (QLD has no DST; moved from 8pm on 2026-09-02). First `vercel.json` in the repo; a 9am health check (`0 23 * * *`) runs alongside it.
  - **The morning check email links into the Command Centre (2026-10-15, Rhys).** Each stuck tender is a link to `/admin/tenders?item=<tender_items.id>` (one per title — reminders duplicate rows), and every email ends with an "Open Tender Watch" button. `?item=` makes the view open on whichever list holds that tender NOW (it may have been sent since) with its card outlined and scrolled to; an id no longer listed shows "most likely closed". `/admin` only — the staff tool page ignores it.
  - Two phases, both resumable off partial indexes: fetch+persist (raw stored *before* parsing, so a format change is replayable) then classify+forward. No retry queue — tomorrow's run is the retry.
  - `lib/tenders/*`, migration `0006`, `lib/html.ts` (hardened escaping), `lib/auth/shared-secret.ts` (fail-closed cron gate).
  - The tool is a **server** component (`index.tsx` loads, `view.tsx` renders) — unlike the other tools, because a dashboard must show state on open.
  - ⚠️ `tender_upsert_item`'s `on conflict do update` refreshes only source-owned fields. Widening it re-classifies and re-emails the whole back-catalogue nightly.
  - **Sending is MANUAL and there is no switch for it.** `/staff/accounts/tools/tender-watch` opens on a work queue: tick the opportunities worth chasing, press **Send email**, and a handoff goes to `TENDER_NOTIFY_EMAIL` (→ `ADMIN_EMAIL` → `info@ausdilaps.com.au`). **Dismiss** archives without emailing. Both write columns `0006` already shipped (`forwarded_at` / `status='archived'` + `reviewed_by`), so no migration was needed. Anyone in **accounts** can send — they can already read every tender, and the recipient is our own inbox.
    - This retired an automatic nightly digest along with `TENDER_FORWARD_ENABLED`, `TENDER_FORWARD_UNTRUSTED` and the trusted-sender gate — three settings whose only job was making *unattended* sending safe. `is_trusted` survives as an informational badge. Don't reintroduce the auto-digest beside the manual path: two senders will double-send the same tender.
  - ⚠️ **Five `tender_scan_runs` counters are declared and never written** (`items_classified`, `items_matched`, `items_forwarded`, `items_prefiltered`, `items_errored`) — a run row is per-source and closes at the end of Phase A, while classification is one pass over the whole queue afterwards, so there is no source to attribute a match to. Anything the dashboard reports about classification is counted from `tender_items` instead. **Do not "fix" this by writing them**; that is the bug that made the page say "329 scanned, 0 matches" above a list of 16. `npm run check:summary` asserts every figure is reproducible by counting rows.
    - The same dead column silently disabled `DAILY_CLASSIFY_BUDGET` for the tool's whole life (`classifiedInLast24h()` summed it, so it always returned 0). Fixed 2026-09-07.
  - **The dashboard has ONE window** — `WINDOW_DAYS` (14, `TENDER_WINDOW_DAYS`). It previously ran four at once (30d stats, 14d funnel, an unwindowed 120-row list, unwindowed queue counts), which is why no two numbers on it agreed. A new figure needing a different span needs a label on screen saying so.
  - **The summary's item list is match/maybe ONLY (2026-10-08).** It used to carry every windowed row with every column, which passed 1,000 rows (~850KB to the browser per visit, mostly classifier rejections) and TRUNCATED the funnel counts while the banner said so. Now: match/maybe rows in full (what grouping needs); `rejected` = the newest `REJECTED_LIST_ROWS` (100) no_match rows with the columns TenderRow renders (reasoning included — the Rejected tab exists to audit the classifier); `rejectedTotal` and every funnel figure (prefiltered/classified/matched/review/sent) are windowed `count: 'exact', head: true` queries. ⚠️ `sent` must be a count across ALL relevances — a no_match row can be forwarded. `check:summary` pins all of it.
  - **Dismiss never touches a SENT row, nor one someone else already dismissed** (filtered on the read AND re-checked in the write with `.is('forwarded_at', null).neq('status', 'archived')`), and every refusal after the request is validated (400 nothing to act on / no email, 409, 502) returns the refreshed summary, which the view adopts and then drops ticks for groups no longer in the queue. ⚠️ The view calls `router.refresh()` after every action (`adopt()`) — required by the app-wide 30s `staleTimes`, see the Command Centre speed note.
  - **The same tender arrives up to 5 times** (portal reminders carry fresh tracking URLs, so `external_ref` and often `content_hash` differ). `lib/tenders/group.ts` collapses them at READ time — never at ingest, because a wrong storage-level key discards a real tender with no trace. 41 rows → 12 opportunities. `suppressIfDuplicate()` in `scan.ts` has never once fired: it carries `.neq("source_slug", ...)`, and nearly every duplicate is *within* one source.
  - **Per-sender extraction (`lib/tenders/sources/extract/`) — FIXED the bulletin bug.** The generic parser split a message on its anchor links and gave every item the whole body as `excerpt`, so a 14-notice TenderSearch bulletin became 14 items each carrying all 14 — titles came out as tracking URLs and one bulletin was classified 14 times at Opus rates. Both big senders label everything (`Location:`, `Closing Date:`, `Contact:`, Felix's `RFQ Owner`), so extraction is deterministic and **free**. 5 bulletins → **47 notices**, each with its own excerpt.
    - ⚠️ **Split TenderSearch on `TS #<digits>`, never "Return to Top"** — the latter mis-split one of five bulletins (13 blocks for 14 notices). The reference is also the `external_ref` (`ts:967459` / `felix:127035`), which is what finally collapses reminder spam on identity: three messages about Felix #126379 are now one row.
    - **Extractors return `null` and never throw.** They are regexes over someone else's HTML; a format change must degrade to the generic parser, not lose the night's mail. Discovery stays domain-generic — a new portal still works with no code change. Fixtures in `__fixtures__/messages.json` are the real bulletins (tracking tokens redacted) from `raw_payload`.
  - ⚠️ **`tender_items.url` means "a link the RECIPIENT can follow".** `singleItem()` used to put Graph's `webLink` there — an OWA deep link into the `tenders@` mailbox that nobody else can open, and valid https so it passed `safeExternalUrl()`. It lives in `mailbox_url` now; `url` stays null when there is no portal and the email says "Invitation by email — reply to <sender>".
  - **`site_location` + `contact` (migration `0013`)** are what make the handoff email self-sufficient — the ask was to read the email and go straight to Salesforce without opening the tool. Populated deterministically for the labelled sources; the classifier's new `location` field covers only the free-prose invitations. ⚠️ It is written as `outcome.extracted.location ?? row.site_location` — follow `agency`'s coalescing pattern, NOT `jurisdiction`'s unconditional assignment, or a model null blanks a good extracted value.
