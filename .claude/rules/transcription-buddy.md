# Transcription Buddy (TRN)

Moved verbatim from the root `CLAUDE.md` §3 on 2026-10-26 so it loads only when working on these files. Project-wide rules (Supabase refs, local dev writes to production, guardrails) stay in the root file.

- **Transcription Buddy (`transcription-buddy`, code `TRN`) — REPORTS department, BUILT 2026-09-18.** Paste Box links to an inspector's dictations (files or whole folders; it was drag-and-drop until 2026-09-23), get the transcript back in EXACTLY the layout Word's Transcribe feature produces (`Audio file` / file name / `Transcript` / alternating `hh:mm:ss` and text lines, files separated by blank lines), one Copy button. That layout is a CONTRACT with the report team's `type-pre-report` skill, which reads Word's output today — `npm run check:transcript` pins it. `lib/transcription/*`, `app/api/transcription/{box-list,from-box,nightly,nightly/log}`, `components/tools/transcription-buddy/{index,manual,daily-runs}.tsx`, `components/tools/shared/copy-text.ts`.
  - **Deepgram Nova-3, pre-recorded, `en-AU`** (`DEEPGRAM_API_KEY`; ~0.43c per audio minute + 0.13c for keyterms, a 15-minute file back in ~15 s). Chosen over AssemblyAI (cheaper, but async submit-then-poll) and OpenAI (25 MB cap, bytes through our server). **Prompted with `keyterm`s** (`lib/transcription/keyterms.ts`): the trade words Word mishears — "yacht" for yard, "tile flows" for tile floors, "base station" for vegetation — PLUS the street name parsed off the FILE NAME (`keytermsFor("11 Emeraldwood st.mp3")` → "Emeraldwood Street"), because inspectors name the recording after the job and the street is the word most likely to come back as a homophone. Deepgram caps the list at 500 tokens; every entry has to earn its place.
  - ⚠️ **BOX LINKS ONLY since 2026-09-23 (Rhys: "let's go to Box links only, and allow a queue of dozens").** The recordings already live in Box, so the tool reads them THERE: paste file or folder links (one per line, `extractBoxLinks` pulls them out of any pasted block) → `/api/transcription/box-list` (`listBoxAudio`: a folder becomes every audio file in it, top level, Box's name order, paged and `cache: "no-store"` — NOT `lib/box`'s `listFolderItems`, which carries `revalidate: 1800` for the samples page and would hide a recording uploaded a minute ago) → each file queued → `/api/transcription/from-box` per file: `resolveBoxAudio` asks Box for the file's SHORT-LIVED DOWNLOAD URL (`GET /files/:id/content` with `redirect: "manual"`; the 302's `Location` is a tokenless dl.boxcloud.com address good for a few minutes) and hands it to `transcribeFromUrl` (`lib/transcription/run.ts`). **Nothing is uploaded, nothing is copied, no bytes pass through a Vercel function, and there is no size cap of ours — only Box's 5 GB.** A shared link the service account cannot see directly is opened with `BoxApi: shared_link=`, and every file listed under a shared folder carries that link (`sharedUrl`) so its download works the same way. A file it cannot open is a plain `BoxSourceError` message. **The drag-and-drop path, `/upload-url`, `/transcribe`, `lib/transcription/storage.ts` and the 200 MB cap are DELETED** — the upload was the slow part (a 110 MB file was a minute or more before anything started; Box → Deepgram is server-to-server and sub-second). ⚠️ **The `dictation` Storage bucket still exists on Sydney and is now UNUSED** — delete it in the dashboard when convenient; migration `0019` is history. Verified live: a folder link listed its one recording, the same file pasted again was reported "already in the queue", a link the account cannot open was reported by name, and the recording transcribed (2 min 15 s, 4.5c) with Box's own name and size on the row.
    - **A queue of dozens**: `BATCH_CONCURRENCY = 3`, the circuit breaker at 3 failures in a row, **Stop after these** (workers finish the file in hand and claim no more — a ref the worker loop reads, mirrored into `stopping` state for the button because a ref may not be read during render) and **Resume**. Listing is free, so the queue shows every name and size before a cent is spent, and the note under the box says what each link yielded ("<folder>: 12 recordings, 2 already queued").
  - **Cleaned by default, raw one click away.** `cleanTranscript()` (`claude-opus-5`, effort low, ~5c a file) fixes ONLY words the speech-to-text plainly misheard and is told the vocabulary and the file-name address; it never rewrites into house style — that is the typing skill's job and it wants the inspector's own words as its source of truth. ⚠️ **Its one invariant is the timestamp lines**: same count, same order, or the pass is discarded and the raw shown (a model that dropped a line has done more than fix words). Degrades, never blocks — a failed pass returns the raw with a note.
  - **Access is department-scoped** (`isStaffInAnyDepartment(TRANSCRIPTION_DEPARTMENTS, …)`), the list imported by BOTH the routes and the registry from `lib/transcription/config.ts` so a card and its API cannot disagree — the Tender Watch arrangement. `/transcribe` is the ONE route that counts a tool use, so a batch of six counts six.
  - **`api_calls` gained a fourth provider, `deepgram`**, priced per audio minute ROUNDED UP (`deepgramCostCents`) — a ceiling, like every provider here. ⚠️ `recordApiCall`'s fallthrough arm records `cost_cents: 0`, so a provider without its own arm shows on `/admin/usage` as free; Deepgram nearly did. Two rows per file (Deepgram + Anthropic), both attributed off the Referer.
  - ✅ **Proven end to end 2026-09-18** on `13 Emeralwood st.mp3` (13.8 MB, 15 min 2 s — three times Vercel's body cap, so it also proved the signed-upload path): bucket self-created on first use, Deepgram back in ~15 s, both usage rows logged under the tool (`deepgram listen` 16 units / 8.96c, `anthropic messages` 6k in / 5.2k out / **16c**), zero objects left in `dictation` afterwards. **~25c a file**, of which the clean-up is two thirds — `TRANSCRIPTION_CLEANUP_MODEL=claude-sonnet-5` would take that to ~6c if it ever matters. Two things the first run taught, both fixed the same day: **lines are SENTENCES** (`paragraphs.sentences`), not Deepgram `utterances` — an inspector dictating while walking pauses mid-sentence, so utterances gave lines reading just "The" and "four is the"; and **the clean-up pass is shown the BODY only** (`splitHeader`) — asked to return "the corrected transcript", the model dropped the three header lines as furniture, and the timestamp invariant cannot see a missing header.
  - **BATCH: `BATCH_CONCURRENCY = 3`, auto-started on drop (2026-09-18).** Rhys asked for batch after seeing a suggestion for a "Transcribe All" button; the queue already existed and already auto-starts on drop, so there is deliberately no such button. **Concurrency is worth having because Deepgram is NOT the slow part** — measured on two real dictations, 25 minutes of audio came back in 4.9 s and 15 minutes in 4.2 s, so the long pole is the Anthropic clean-up (which is also two thirds of the cost, above). What a 27-file run actually needed was three things:
    - ⚠️ **The REF is the queue and `items` only mirrors it.** It was the other way round — a functional `setItems` plus an effect copying state back into the ref — which is correct for one worker and a **DOUBLE-TRANSCRIBE** with three: React has not re-rendered, so two workers' `find()` both see the same file still `queued` and both pay for it. `claim()` marks a file taken in the SAME TICK, and `patch()` now writes the ref then mirrors it.
    - ⚠️ **A CIRCUIT BREAKER at `MAX_CONSECUTIVE_FAILURES = 3`.** A wrong key or an account out of credit otherwise fails all 27 one at a time — and each one has already pushed its megabytes to Storage by the time the transcribe call answers, so you would come back to 27 identical errors and a few hundred MB uploaded for nothing. It stops, says which error to read, and offers **Resume**.
    - **Output is DROP order, never finish order** — with three workers a short file routinely lands before a long one dropped ahead of it. The transcript is built by filtering `items`, which `patch()` only ever maps over, so positions never move. The typing skill reads a batch against the operator's own file list, so this is the order that matters.
    - Progress is one line ("9 of 27 done · 2 failed") AND the **tab title**, because the point of a batch is that you walk away from it and a spinner nobody is looking at tells nobody anything. Retry is no longer disabled while busy — with several workers there is one free to pick it up.
  - ⚠️ **Staff NAMES are keyterms, and they were missing entirely.** A live run transcribed "This is Rhys Morgan" as **"This is Reese Morgan"** — the opening sentence of every dictation is the most predictable phrase in the whole corpus and it was the one thing with no keyterm behind it (54 trade words, zero names). `STAFF_NAMES` is derived from `lib/site.ts` TEAM rather than retyped, as full name + first name; re-transcribed with it, the same file returns "Rhys Morgan" and zero mis-hearings. ⚠️ **TEAM is the COMPANY list, not the people who record dictations** — "This is Ram" in the second test file is someone TEAM does not contain, and may itself be a mis-hearing. **The inspectors' own names are the bigger win and are still outstanding**; the cap is 500 tokens and this uses about a dozen. `check:transcript` pins the composition (street, then names, then vocabulary) rather than the old magic `+1`.
  - **The clean-up pass runs in CHUNKS** (`chunkBody`, 120 timestamp pairs ≈ 15 min each, three at a time) because a two-hour transcript is ~25k tokens — past one response's `max_tokens` and past the route's clock; a chunk that fails keeps its raw text and the note says how many sections.
  - **THREE views, "For typing" the default (2026-09-18, the report team's list via Rhys).** `lib/transcription/trim.ts` is a DETERMINISTIC strip of everything the typing skill does not read: the greeting, the "today I'm going to do the pre-inspection at …" intro, temperature, weather, the sign-off and any thank-you, the door-knock / work-order / external-only preamble, "that is the only photo I could capture"; plus leading "so"/"now", "just" and "please" anywhere, "which is" as a connector before a photo number, and "along with" → "and". Runs AFTER the model clean-up (which needs every line for its timestamp invariant), never touches the header, and a dropped line takes its timestamp with it. **Code, not a model, on purpose**: free, identical every time, and a misfiring rule is a one-line fix pinned in `check:transcript` against lines out of the real dictations. Cleaned and Raw stay one click away for anything it removed; the note under the toolbar says how many lines went. Copy takes whichever view is showing. The inspectors' side of the same list — figure number, element, location, defect, "major" — is `content/training/inspectors/dictating-for-transcription.mdx`, the inspectors' first training module.
  - **Self-corrections are RESOLVED and garbled figure numbers are FLAGGED, never cut (2026-09-18, the report team via Rhys).** Both need judgement, so they live in the clean-up prompt (`lib/transcription/cleanup.ts`): "the fine gap on the west wall or this should be the east wall or no, the south wall" → "the fine gap on the south wall of the house" (verified live on the Emeralwood recording; "the west yard north yard" → "the north yard"); when it is genuinely unclear which was meant the line keeps both and gets `[CHECK: west or south wall?]`. A garbled number ("300And34", "Hundred And 20", "fifty five years") stays as heard with `[CHECK NUMBER: …, likely 55]` appended — and the model also flags a number that breaks the photo sequence ("112, likely 122"), which is a real catch, not noise. **Flags are INLINE text on the END of the line**, deliberately, so they travel with the copy into the typing skill; `CHECK_FLAG` in `trim.ts` is the one regex that recognises them, the trim never strips one, `flagGarbledNumber()` is a deterministic safety net under the model for the obvious digit-glued-to-word patterns, and the UI counts them in an orange note ("6 lines flagged [CHECK] — search the text for "[CHECK" before typing"). ⚠️ The flag count is computed on the VIEW being shown, so For typing reports fewer than Cleaned when a flagged line was one the trim dropped (the intro line's suburb flag, typically).
  - ⚠️ **The tool does NOT show its own API cost — removed 2026-09-22 (Rhys: "API cost inside the tool itself doesn't need to be visible. It can just stay in the admin backend for me").** `components/tools/shared/tool-spend.tsx` and `app/api/tools/usage/route.ts` are DELETED, along with the `<ToolSpend>` line from all five tools that mounted it (Transcription Buddy, Floor Plan, Cover Photo, Overview Markup, Markup and Measure) and the `paidActions` / `tabSwitches` / `sessionCents` state that existed only to feed it. Cost lives on **`/admin/usage`** only. Transcription Buddy's `/transcribe` still RETURNS `costCents` per file — the per-row figure is gone from the UI but the number is still there if a counter is ever wanted back. Don't re-add an in-tool counter without asking; this was built, shown and rejected.
  - **`/admin/usage` got the breakdown to go with it (2026-09-18):** `?month=YYYY-MM` shows any past month against the one before it (Brisbane months; a future month clamps to the current one), a tile per PROVIDER present (Google and Anthropic always, Deepgram and any later one when it spent), and **each tool row opens (`<details>`, `?tool=<slug>` opens it) to the APIs its money went on**, with a Units column that knows what it is counting (`unitLabel()`: audio minutes, requests, tiles, calls). The By API table gained the same Units column. ⚠️ **Reads are NOT gated on production** — only writes are — so localhost shows the live month's real figures; that is deliberate, it is how the page is checked without a row ever being written from a laptop.

  - **NIGHTLY CRAWL — the Daily runs tab (BUILT 2026-09-23, Rhys + Brittany: "have it crawl the daily upload folder so the text is ready to copy").** Transcription Buddy now has two tabs, **Manual** (the paste-a-link tool, `manual.tsx`, unchanged) and **Daily runs** (`daily-runs.tsx`). From **4am SYDNEY** every morning the automation walks YESTERDAY's (Sydney) folder in Box **Inspector Uploads** (`304525890531`, `TRANSCRIPTION_UPLOADS_FOLDER_ID`): `<year> / <month> / <day> / <inspector initials> / *.mp3`, two levels below each inspector folder searched too. `lib/transcription/nightly/*`, `/api/transcription/nightly` (GET = cron bearer `CRON_SECRET`; POST = admin **Run now** for any past day), `/api/transcription/nightly/log` (the tab's reader), migration **`0025`**.
    - ⚠️ **The transcription is NOT re-implemented, on Rhys's explicit instruction.** Each recording goes through `resolveBoxAudio()` → `transcribeFromUrl()` — the exact functions the Manual tab's route calls — so the model, prompt, keyterms, trim and `[CHECK]` flags are identical by construction. The nightly code only decides WHAT is fed in and keeps its own log. Don't give it its own model or its own clean-up.
    - **TICKS, not one run.** Cron `*/10 17-20 * * *` UTC — every 10 minutes across a window covering 4:00–7:50am Sydney in AEDT and 4:00–6:50am in AEST; ticks before 4am Sydney return at once, because Vercel Cron is UTC and NSW changes its clocks (`dates.ts` uses `Intl` with `Australia/Sydney`, never a fixed offset; `check:transcript` pins the 4 Oct change). A night is ~20–30 files and one function lives 290 s, so each tick: takes a 5-minute LEASE on the night (one tick at a time; a killed tick frees it), re-lists the day folder (free, so a 5am upload is caught), transcribes queued files three at a time, stops STARTING new ones after 150 s, and resets any row stuck `transcribing` for 8 minutes. A file gets 3 attempts across ticks, then `failed`. `box_file_id` is UNIQUE and the upsert is `ignoreDuplicates`, which is what makes a recording transcribed once however many ticks see it. `TRANSCRIPTION_NIGHTLY_MAX_MINUTES` (600) caps a night; the rest is marked `skipped` and reported.
    - **Output: a `.txt` of the For typing view beside each recording in Box** (`uploadFileAutoRenamed`, so an existing name steps to "(2)"), plus all three views in the tab with Copy. The service account is a **Viewer Uploader** on Inspector Uploads (verified 2026-09-23: `can_upload` true, `can_delete` false) — least privilege.
    - **The REAL tree (walked 2026-09-23):** `2026 / 09. September / 220926` — ⚠️ **day folders are DDMMYY with no separators** (`compactDate()` in `dates.ts`; the first cut would have matched none of them). Discovery of a 26-job day takes ~14 s.
