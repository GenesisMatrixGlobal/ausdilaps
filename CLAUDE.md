## 1. What this is

A ground-up rebuild of **ausdilaps.com.au** for **AusDilaps — Specialist Building Inspections**, Australia's specialist **dilapidation (building condition) report** firm. ~$5M revenue, family-owned, 15 years, team <50. Legal entity **Urban Pulse Strategies Pty Ltd T/A AusDilaps**, ABN **82 650 700 226**, Albany Creek / Aspley QLD, Australia-wide.

It replaces an old WordPress/Tatsu site (kept locally as a read-only reference at `20260616-AusDilaps-WordPress/` — git/vercel-ignored). The live old site still ranks for hundreds of terms; **we must preserve that** (see §7).

**This repo is one thing: a marketing + lead-generation + content platform.** There are **NO client logins** here. A future client portal will be a **separate system** — do not build it here.

## 2. The vision — the best this can be

Not a brochure. The goal is to make AusDilaps **the category authority** in Australian dilapidation reporting:

1. **SEO + AEO + GEO dominance.** Own the informational long tail, win the AI overviews / featured snippets / People-also-ask / local packs already showing on these terms, and become the **source LLMs cite** (GEO: structured data everywhere, answer-first copy, E-E-A-T, `llms.txt`).
2. **Expansive & deep.** Every service, sector, location, and the full 22-project portfolio — each a real, schema-rich page. Not consolidated away; the long tail is the moat.
3. **A content & news engine** that makes AusDilaps the voice of the industry — natural events (earthquakes, storms, cyclones, floods), major projects (Brisbane 2032, Sydney/Melbourne tunnels), dilapidation knowledge, and **advocacy** (lobbying state governments to adopt compulsory dilapidation reporting — the NSW model). This is the thought-leadership + lobbying platform.
4. **A conversion machine.** Every page routes to a qualified quote. The form captures real project detail, classifies the lead (Tier-1 vs residential), and pushes to Salesforce.
5. **Craft an engineer is proud of.** Fast, accessible, precise, beautiful. Hybrid light/charcoal design from the logo.

**Positioning line to build around:** *AusDilaps is the Tier 1 dilapidation specialist Australian contractors and government agencies trust when a damage claim has to be defensible, not just delivered.* (StoryBrand: the customer — a project manager / contracts admin / council risk officer — is the hero; we are the guide with Tier-1 proof + chartered engineers.)

  - **One rule: geometry flows one way, Google's overlay → React.** Every mutation (map click, vertex drag, midpoint insert, undo, clear, right-click delete) writes into the overlay's `MVCArray`; `syncFromOverlay()` mirrors it into state, which only the panel reads. React writes geometry back in exactly ONE place — `createOverlay()`, before any listener is attached, which doubles as the rehydrate path after a tab switch. The tempting alternative (reconcile both ways, guarded by a "we're writing" ref) fails not as a loop but as a **stale frame**: the map is at path N+2 while React renders N, the reconcile pushes N back, and the vertex under your finger jumps backwards.
  - The reconcile effect is keyed on a **structural signature string** (`id:mode:width` per shape + activeId), never the shapes array — so it doesn't even run during a drag. Whole-shape drag was right on the static image; here it is a liability.
  - ⚠️ **Building Markup draws its OWN vertex handles** (`vertex-handles.ts`) and keeps `editable: false` always. Google exposes no way to resize its handles — `PolygonOptions`/`PolylineOptions` are only `clickable, draggable, editable, fill*, geodesic, map, paths, stroke*, visible, zIndex`, and the handle geometry is inline-styled on obfuscated elements, so a CSS override fights Google's own drag maths. The cost is that Google's midpoint "ghost" handles go with `editable`, so they are rebuilt here: a midpoint's `dragstart` does `insertAt` and the ghost becomes a real vertex under the finger. `google.maps.Marker` + `SymbolPath.CIRCLE`, NOT `AdvancedMarkerElement` — that needs a `mapId`, which switches the map to vector, discards `styles` and breaks the OverlayView badges. Handles exist only on the selected shape, so ≤20 + ≤20 markers, not hundreds.
  - ⚠️ **A drag must never rebuild the handle set.** Handles are derived from the path and the path changes every frame while dragging, so a naive rebuild destroys the marker under the operator's finger. A `dragging` ref defers rebuilds to `dragend`. Same class of failure as the stale frame above.
  - ⚠️ **`paths: [ring]`, never `paths: ring`, when constructing a Polygon.** Google reads a bare empty array as "no rings at all", so `getPaths()` comes back empty and `getPath()` is UNDEFINED — and the next line, `mvc.addListener()`, throws. Hit in production: add a shape, switch it to Area before placing a point, white screen.
  - **A rejected Maps key is INVISIBLE without help.** The script loads, `google.maps` exists, `new Map()` returns an object, and then nothing paints — just a console error and a blank grey box. `lib/maps/loader.ts` installs Google's `gm_authFailure` global and exposes it as a subscription (it fires AFTER the loader has resolved, so it cannot be a rejected promise); both maps show a message naming the fix.
  - ⚠️ **`clickableIcons: false` is load-bearing**, not cosmetic: a POI pin otherwise opens an info window and *eats* the click meant to place a point, and hybrid over an Australian suburb is covered in them. Likewise the overlay's own `click` handler calling `e.stop()` then placing the point itself — without it you cannot add a fourth point inside the triangle you just drew.

Building Markup's file (`lib/maps/building-markup-file.ts`) stores the RESOLVED cadastre geometry, not just the address — re-resolving on open would hand back whatever the cadastre says today, which is not the drawing that was signed off. The basemap PNG is deliberately not stored; `/render` reproduces it from the saved frame.
  - **Save .json / Open .json** (`lib/maps/measure-file.ts`) lets a set be reopened and adjusted. Stores geometry ONLY — never a derived area, which would become a second source of truth that disagrees with `measureShape()` the moment the maths improves — plus the frame, so reopening flies back to it. Ids are regenerated on open; a bad field drops its own shape and is counted, not the whole file. There is no automatic persistence, deliberately: these are scratch measurements, and a silently-restored set from last week is a worse default than an empty map.
  - Needs **`NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_KEY`** — a SECOND, separate key from `GOOGLE_MAPS_API_KEY`. Never merge them: the server one carries Geocoding, Directions and Static Maps quota, and Maps JS puts its key in the client bundle by design. Without it the Measure tab shows a "not configured" message and every other tab is unaffected.

- **Per-lot street addresses (BUILT).** `lib/kml/standard-markup/parcels/addresses.ts` — every state publishes an address layer on the SAME free, keyless ArcGIS service the parcel adapters already use, so this costs no key and no Google quota. QLD joins on `lotplan` (attribute, one call for every lot); NSW and VIC have no lot id so they join spatially against the rings.
  - ⚠️ **This module must NEVER throw.** The parcel adapters throw on failure and should — without a boundary there is no markup. An address is a convenience: a failed lookup returns an empty map, the cells come up blank and the operator types them.
  - ⚠️ **NSW needs `where=principaladdresstype=1`.** Without it one suburban block returns 189 rows (every unit of every strata block) instead of 5 properties. And an envelope given only TWO coordinates is silently accepted and answered with arbitrary features from elsewhere in the state — always emit four.
  - **VIC: use `ezi_address` whole**, never reassembled — `road_type` is null for some roads and `house_number_1` is an integer, so it drops the `A` in "91A". `is_primary` is "Y" on unit rows too, so dedupe by `property_pfi`.
  - ⚠️ **One QLD lotplan can hold FOUR addresses** and not only for strata: 15RP815277 at Aspley is a corner lot addressed off Maundrell Tce, Riordan St, Albany Creek Rd and Gympie Rd, with no primary flag. The pick is deterministic (prefer the subject's street) and the alternatives are surfaced as a markup flag rather than hidden.
- **`lib/arcgis.ts` — a failed ArcGIS query arrives as HTTP 200 with `{"error":{...}}` and no `features` key.** Every reader here used to do `body.features ?? []` and read an outage as "there is nothing here", so the cadastre tools told the operator *"no titled parcel at this address — measure manually"* and blamed the address. Load-bearing queries now throw; the address enrichment logs and degrades. Bulk Property Sizing told the same lie and is fixed the same way.
- ⚠️ **VIC's parcel cadastre has a fallback, and it is there because it FAILED in production** (2026-09-08, mid-session). `Vicmap_Parcel` began rejecting every spatial query that returns records — "Cannot perform query. Invalid query parameters.", while `returnCountOnly` kept working — and its feature count dropped to 120,400, about 3% of the state, with `parcel_lga_code='HOBSONS BAY'` and `='MELBOURNE'` both counting ZERO. So a fixed query would still have found nothing. `parcels/vic.ts` tries the parcel layer FIRST every time and falls through to `Vicmap_Property` (4.19M features, untouched throughout), so it returns to true cadastral parcels the moment VIC restores the layer, with no switch to flip.
  - The cost: a property PFI is not a title reference, so lot/plan is blank while the fallback is in use — `parcels/parcel-id.ts` is the single place that decides whether an id may be shown as a lot/plan — and `resolve.ts` flags it on the markup.
  - ⚠️ **Property views must be deduplicated by outline.** A strata development has one property row per tenancy, each carrying the WHOLE parcel outline: the shopping centre beside 88 Kingsway, Glen Waverley arrived as 13 identical 10,464 m² polygons and would have eaten 13 numbered pins.
- **Quote Line Item sheet (`lib/markup-layers/`, TEST-GRADE).** The spreadsheet under the Building Markup image: one row per layer, with product, asset type, internal/external m² and per-row rates. ⚠️ **The products in `salesforce-picklists.ts` are PROVISIONAL** and the asset types are the org's real 9-value picklist. **Nothing writes to Salesforce** — `lib/salesforce.ts` still has only `soqlQuery` and `updateRecord`, a QuoteLineItem insert needs a `PricebookEntryId` this repo has never read, and the run-as user has never exercised Create on that object. `npm run dry-run:lines` renders the sheet offline from a saved `.json`.
  - Cells are held as STRINGS, the way a spreadsheet holds them, and parsed on read — numeric state fights the operator on every keystroke and rounds "0.80" to "0.8" in a currency column.

- **Knowledge base (BUILT — ingest + keyword search):** the corpus behind the department search bar. Migrations `0009`/`0010`, `lib/knowledge/*`, `/staff/<dept>/training/manage`, search bar on `/staff/<dept>/training`.
  - **The unit is a CHUNK, not a file.** A 90-minute video is a useless result; "14:22 — ring the subject lot first" is the product. Every chunk stores an `anchor` (prose) or `start_seconds` (transcript) to deep-link back.
  - `lib/slug.ts` is the contract between `components/marketing/markdown.tsx` (which puts ids on headings) and `lib/knowledge/chunk.ts` (which stores them as anchors). **Change the slug rule in one place or every citation link silently lands at the top of the page.**
  - `knowledge_sources.body` holds the extracted text as the source of truth, so the chunker can be improved and everything re-chunked without anyone re-uploading.
  - **Reads are scoped by RLS, not app code** — retrieval must use the user-scoped client (`lib/supabase/server.ts`). Uses `is_staff()`, NOT `is_internal()`: the latter is admin-only and made the whole base invisible to ordinary staff.
  - `profiles.can_manage_knowledge` lets a department lead upload without being an admin. Publishing needs membership of EVERY department tagged on the content; company-wide (`departments = '{}'`) is admins only.
  - `npm run index:training` indexes `content/training/**/*.mdx` into the same corpus, and **runs automatically on every production deploy** via the `postbuild` hook in `package.json`. Adding a module is now just committing the `.mdx`.
    - The hook is `--on-deploy`, which differs from a manual run deliberately: it **only runs when `VERCEL_ENV=production`** (one Supabase project, no dev database — otherwise every local `npm run build` and every branch preview would write its own copy into live search), it **never fails the build** (a module that won't index is not a reason to stop shipping the site), and it **skips modules whose stored `body` is unchanged**, so a deploy that touched no training content does no writes.
    - A manual `npm run index:training` always re-indexes everything — that's what to run after changing the chunker (`lib/knowledge/chunk.ts`), which is exactly why `body` is stored.
    - Both modes **prune**: delete a module or flip it to `draft: true` and its knowledge source goes with it. Without that, search keeps confidently citing a page that 404s. Pruning only touches `kind='training'` rows and is scoped to the departments in the run, so `-- reports` can't delete another department's modules.
  - **Retrieval is BUILT** (`0010`, `lib/knowledge/retrieve.ts`, `components/staff/knowledge-search.tsx`): Postgres FTS, no embeddings, no model, no per-query cost. `search_knowledge()` is **`security invoker`** — RLS is the only thing scoping this corpus, and the `dept` argument is a second filter, not a substitute. Verified: a reports-only account reading `knowledge_chunks` directly gets zero rows.
    - `0010` also fixed two things that made naive FTS useless: source **titles** weren't in any search vector, and `websearch_to_tsquery` ANDs every term so one unmatched word returned nothing (`or_query()` widens it; ranking still floats full matches).
    - Snippets come back with `«match»` markers, not `<mark>` — `ts_headline` doesn't escape source text, so HTML would let an uploaded document inject markup. The client builds its own `<mark>`.
    - `components/staff/scroll-to-hash.tsx` is what makes `#heading` citations land on the heading; the browser resolves a hash before streamed content exists and silently gives up at the top of the page.
  - **Uploads are browsable** — `/staff/<dept>/training` lists them beside the MDX modules, each with its own page at `/staff/<dept>/training/knowledge/<id>`. Both the list and that page require the source to be tagged for the department in the URL (or company-wide): RLS is not enough on its own, because `has_department()` returns true for admins everywhere.
  - **Context + AI indexing (`0011`, `lib/knowledge/{ai,vision,summarise}.ts`).** The uploader answers three questions — what it covers / when you'd need it / what we call it internally — and those are fused with the document into an `ai_summary` + `ai_keywords`.
    - **Every PDF is read visually** by `claude-opus-5` (native PDF input — text AND images, no beta header). The transcription REPLACES `body`, so it is chunked and cited; that is only legitimate because it is a transcription, and the prompt forbids summarising. Proven on a PDF with **zero** extractable text: it produced headings, described where the buttons were, and read the values inside the screenshots.
    - **`ai_summary`/`ai_keywords` are SOURCE-level and never enter `knowledge_chunks`.** A chunk is what gets quoted back as the document's own words; a summary is the model's reading of it. Putting context into chunks would also make every chunk of a document match equally and destroy the ranking that picks the right passage.
    - `0011` weights the source vector with `setweight`: **A** title, **B** summary + ai_summary, **C** context + ai_keywords. Replaces 0010's repeat-the-title-twice hack, which does not survive fields of wildly different lengths.
    - ⚠️ `ai_keywords` is `text`, not `text[]` — `array_to_string()` is `STABLE`, so Postgres rejects it inside a generated column.
    - **Cost is one-time per document.** Search stays pure FTS at $0.00, and re-index re-chunks from the stored `body`, so vision is never re-paid. ~$0.15 per 10-page PDF.
    - **The AI path degrades, never blocks.** Every call returns a result object and is caught; a failed vision pass leaves the plain text extraction in place. Verified in the wild — a vision call 400'd and the row still indexed cleanly.
    - `ai_summary_edited` stops a re-index overwriting a human correction. Clearing the summary hands it back to the model.
  - **NOT built: the AI answer layer.** Deliberate — the corpus is tiny, and an LLM answer over a thin corpus is worse than an honest empty result. Add it once there's real volume. The Phase 4 pgvector migration is written in a comment in `0009`; triggers are ~1,500 chunks or a tail of should-have-matched misses in `knowledge_queries` (now being logged).
  - ⚠️ **`STAFF_PREVIEW=1` fakes the app user but NOT a Supabase session**, so RLS sees an anonymous caller and search returns nothing. It looks like an empty corpus, not an auth problem. Sign in properly to test retrieval.
  - The old shared `ADMIN_ACCESS_PASSWORD` gate is **gone** (`lib/auth/admin-session.ts` and `/api/admin/login` deleted). The per-tool `*_ALLOW_UNAUTHED` env hatches are now **dev-only** — they used to leave those API routes open in production.
- **Samples page (RESOLVED — was the pre-cutover blocker):** `/dilapidation-reports/samples` renders from Box, and the static `FALLBACK_CATEGORIES` list that linked LIVE WordPress PDFs has been **deleted** — post-cutover `ausdilaps.com.au/wp-content/...` resolves to this site, so those 19 links would have 404'd. Box is now the only source and the page 404s if it can't be read; ISR keeps serving the last good render, so a Box blip never reaches a visitor, and `lib/box.ts` uses `Promise.allSettled` throughout so one bad file or subfolder can't take the page down. See `docs/box-samples-sync.md`.
