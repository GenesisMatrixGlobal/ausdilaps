## 1. What this is

A ground-up rebuild of **ausdilaps.com.au** for **AusDilaps — Specialist Building Inspections**, Australia's specialist **dilapidation (building condition) report** firm. ~$5M revenue, family-owned, 15 years, team <50. Legal entity **Urban Pulse Strategies Pty Ltd T/A AusDilaps**, ABN **82 650 700 226**, Albany Creek / Aspley QLD, Australia-wide.

It replaces an old WordPress/Tatsu site (kept locally as a read-only reference at `20260616-AusDilaps-WordPress/` — git/vercel-ignored). The live old site still ranks for hundreds of terms; **we must preserve that** (see §7).

**This repo is one thing: a marketing + lead-generation + content platform.** There are **NO client logins** here. A future client portal will be a **separate system** — do not build it here.

---

## 2. The vision — the best this can be

Not a brochure. The goal is to make AusDilaps **the category authority** in Australian dilapidation reporting:

1. **SEO + AEO + GEO dominance.** Own the informational long tail, win the AI overviews / featured snippets / People-also-ask / local packs already showing on these terms, and become the **source LLMs cite** (GEO: structured data everywhere, answer-first copy, E-E-A-T, `llms.txt`).
2. **Expansive & deep.** Every service, sector, location, and the full 22-project portfolio — each a real, schema-rich page. Not consolidated away; the long tail is the moat.
3. **A content & news engine** that makes AusDilaps the voice of the industry — natural events (earthquakes, storms, cyclones, floods), major projects (Brisbane 2032, Sydney/Melbourne tunnels), dilapidation knowledge, and **advocacy** (lobbying state governments to adopt compulsory dilapidation reporting — the NSW model). This is the thought-leadership + lobbying platform.
4. **A conversion machine.** Every page routes to a qualified quote. The form captures real project detail, classifies the lead (Tier-1 vs residential), and pushes to Salesforce.
5. **Craft an engineer is proud of.** Fast, accessible, precise, beautiful. Hybrid light/charcoal design from the logo.

**Positioning line to build around:** *AusDilaps is the Tier 1 dilapidation specialist Australian contractors and government agencies trust when a damage claim has to be defensible, not just delivered.* (StoryBrand: the customer — a project manager / contracts admin / council risk officer — is the hero; we are the guide with Tier-1 proof + chartered engineers.)

  - **One rule: geometry flows one way, Google's overlay → React.** Every mutation (map click, vertex drag, midpoint insert, undo, clear, right-click delete) writes into the overlay's `MVCArray`; `syncFromOverlay()` mirrors it into state, which only the panel reads. React writes geometry back in exactly ONE place — `createOverlay()`, before any listener is attached, which doubles as the rehydrate path after a tab switch. The tempting alternative (reconcile both ways, guarded by a "we're writing" ref) fails not as a loop but as a **stale frame**: the map is at path N+2 while React renders N, the reconcile pushes N back, and the vertex under your finger jumps backwards.
  - The reconcile effect is keyed on a **structural signature string** (`id:mode:width` per shape + activeId), never the shapes array — so it doesn't even run during a drag. Live props come from a `latest` ref, assigned in an effect declared FIRST (effects run in declaration order, and the React compiler lint forbids ref writes during render).

Two tools must never quote different square metres for the same outline — `style.ts` already exists in that folder because two copies of the same constants drifted once.

    - **Two scales now, not one (2026-09-11): `LEGEND_SCALE = 2/3`, `NORTH_ARROW_SCALE = 1`** — Rhys looked at real exports and asked for the key at a third of its 2x size and the arrow at half; the chrome was crowding the lots on an estimator's drawing. The history below is why they were 2x to begin with. **`OVERLAY_SCALE = 2`** (the old single factor) scaled the legend AND the north arrow. At 1x the key was a postage stamp on a ~1400px export that gets printed inside a report. Both are drawn at natural size around the origin and scaled as a GROUP — the labels are pre-baked outlines with the glyph size inside the path data, so there is no font size to turn up, and only a group transform keeps the panel, its radius, its border and its text in proportion. ⚠️ The north arrow is positioned by its SCALED footprint (`(nativeSize - MARGIN) / OVERLAY_SCALE`) or it runs off the right edge. Deliberately NOT proportional to the image width: export dimensions follow the operator's viewport aspect through the tiling planner, so a proportional rule would size the key differently on every drawing of the same job. The numbered pins are NOT scaled — they sit on the geometry and would start hiding it.

A key explaining a colour the reader cannot see invites "so where is the project site?". Whole-shape drag was right on the static image; here it is a liability.

Hit in production: add a shape, switch it to Area before placing a point, white screen.

Likewise the overlay's own `click` handler calling `e.stop()` then placing the point itself — without it you cannot add a fourth point inside the triangle you just drew.

  - ⚠️ **`MAX_POINTS = 100` in `measure-shapes.ts` is NOT the Residential tab's `MAX_SHAPE_POINTS = 20`.** That 20 exists because its shapes are percent-encoded into a Static Maps URL with a length limit. Unifying them would either truncate a road frontage at 20 clicks or break the URL.
  - Tabs are **mounted-once-visited, then kept mounted** — unmounting throws away a half-drawn set of measurements, but mounting all three up front would build the map (a billed Dynamic Maps load) on every visit.
  - **Open in Street View** (`lib/maps/street-view.ts`, `street-view-link.tsx`, `/api/maps/street-view`) — Google's yellow pegman, ONE button in the markup-level row beside Sync To Salesforce. It briefly also had an icon per Quote Line Item row; that was removed on request — the site is what an estimator wants to look at, and eleven columns did not need a twelfth affordance. The pegman's colours are hard-coded rather than `currentColor`: it is a recognised third-party mark and the point of drawing it is that an estimator already knows what it does, so it does not tint on hover.
    - ⚠️ **Google's docs are WRONG about the default heading — the heading must be sent.** The Maps URLs reference says that with `heading` absent, "a default heading is chosen based on the viewpoint ... and the actual location of the image". The desktop web client does not do that: tested at Newport, two viewpoints 30 m apart on OPPOSITE bearings from the same camera returned a byte-identical canonical URL (`3a,90y,90t`, no `h` term, `yaw=0` — due north both times). No quota is consumed" — and the billed image endpoint is never called. Server-side both because the web services reject a referrer-restricted key and because that key is never published. ⚠️ Maps JS `StreetViewService.getPanorama()` was rejected on purpose: Google documents "Dynamic Street View is billed per panorama" and exempts nothing for metadata. Headings verified against hand calculations to 0.1°: Bullaburra 323.2, Aspley 359.8, Newport 107.4.

The client stores the heading **with the key of the point it was measured from** and matches during render, so a stale heading is structurally impossible and the effect needs no synchronous `setState` — which the React compiler lint rejects.

  - **Both** address boxes take a **pasted Google Maps URL or a bare `lat, lng` pair** (`lib/maps/parse-google-maps-url.ts`, pure and handled entirely client-side — no Places call). Measure only needs a coordinate, so it just flies there. **Building Markup needs an ADDRESS** — its cadastre lookup is by street/suburb/state — so a coordinate goes through `/api/maps/reverse-geocode` (Geocoding API on the server key, same precision bar as `lib/property-sizing/google-geocode.ts`: a suburb- or state-level hit is rejected, because feeding one to the cadastre returns a convincing-looking random parcel) and the result flows through `handleAddressSelect` exactly as a Places pick does. A place NAME is handed back to `AddressSearch` as a string so Places parses the components properly and it costs nothing extra. ⚠️ The pasted point is kept for Street View **even when the reverse geocode fails** — "look at where this link points" is the one thing a bare coordinate can always deliver. - **Site Snap (`site-snap`, code `SNP`) — the staff game.** Top-down pixel photo survey: walk the house, photograph all 24 walls (four per room) from the centre of each room, inside a 60-second clock. Shared leaderboard, migration `0014`. Replaced a Ping Pong prototype that was never committed and whose table was never created.
  - **The engine is DOM-free** (`engine.ts`) so `npm run check:sitesnap` can drive thousands of runs headlessly. That script is the point: it asserts the house is completable, that the player cannot clip a wall, and — the one that matters — that **the best strategy is neither extreme**. Two earlier designs failed it, both the same way Pong's first build did, by letting a competent player saturate the scoring.
  - ⚠️ **The FOCUS meter is the whole game and it is EXPONENTIAL, not linear.** Standing still, the camera steadies with a time constant; quality is `centre x focus`. Linear focus made quality and the clock both linear in time spent, so the trade never peaked and every strategy scored within 4% of the others. Focus is also consumed PER SHOT — with it persisting, one wait covered all four walls of a room and quality outvalued the clock ~12x.
  - ⚠️ **The time bonus pays ONLY on a complete survey.** Without that, the best play is to shoot the easy half of the house and go home. `BONUS_PER_SECOND` is the single balance knob; tune it, not the quality curve, and re-run the check.
  - ⚠️ **The cat and the toddlers punish OPPOSITE behaviours, and that is the whole reason both exist.** The cat pathfinds after you and zeroes the focus meter when it reaches your ankles, so standing still — exactly what the focus meter asks for — is never free. The toddlers only trip you while you are MOVING (flat on your back for 1.3s, no shooting), so sprinting between rooms is never free either. Neither hazard has a strategy that beats it, so the player has to keep switching. Change one of them to punish the same thing as the other and the middle of the run goes flat again.
  - ⚠️ **Every hazard must BACK OFF after it lands a hit, and must be escapable.** Both retreat across the house for ~2.5s, and a trip is followed by 1.4s of immunity. Without that a cat can camp a room and a toddler can chain-trip, making the survey uncompletable and the completion bonus unreachable through no fault of the player. Same trap the cat's first "refuse the shot" version fell into — the fix there was that it SPOILS a shot (x0.4) rather than refusing it.
  - Chasers path with a BFS in `house.ts`, re-planned every 0.35s rather than per frame. Homing straight at the player and sliding along walls leaves a cat wedged in a bedroom while the player works two rooms away — a hazard that cannot reach you is scenery.
  - ⚠️ **Do not give a bot "stand still when a toddler is near".** It reads as the obvious counter (trips need a moving player) but it DEADLOCKS — they home on you, so stopping means stopping forever. Every bot given that rule froze in the hallway and scored ~500 against ~3450 for one that walked on and ate the occasional trip. Steering around them is the player's job; the sim does not model it.
  - **The plan is 36x21 tiles with a one-cell margin of lawn, six rooms and a fenced BACKYARD — 28 capture targets, not 24.** The yard is a real target, not scenery: photographing boundary fences and external elevations is a genuine part of a survey, so the run finishing outdoors is the most true-to-life thing in the game. ⚠️ **36 columns is a hard ceiling, not a preference** — the tool column is ~1176px, so a canvas wider than 588 logical px can no longer scale by a whole 2x and drops to 1x. Every column added has to come out of another.
  - ⚠️ **Everything unclaimed by a room is SOLID, which is right for collision and wrong for drawing.** `isStructural()` (adjacent to any room cell) is what separates built wall from open ground; without it the lawn margin renders as cream wall and the house looks embedded in a block rather than sitting on a block of land.
  - **The house is baked ONCE into an offscreen canvas and blitted each frame** (`bakeStatic()`). Floors, walls, windows, props and the yard never change during a run, so re-issuing ~900 fillRects at 60fps to redraw a floor that has not moved was the easiest waste in the file to remove. Only capture status, room markers, actors and effects draw live.
  - ⚠️ **The shutter flash decays CUBICALLY.** Punch is a high peak that clears fast: the quadratic version held the screen over 50% white for ~0.16s, which across 28 shots spends a real fraction of the run unable to see the house. A refused press fires a short red `dud` pulse instead of nothing at all — without it, pressing space out of position read as an unresponsive control and players pressed harder rather than moving.
  - Walls occupy CELLS here, unlike `lib/floor-plan`, which puts them on grid lines. That turns collision and doorways into a `solid[y][x]` lookup. `buildOwnerGrid` was deliberately NOT reused: it value-imports `./types`, which drags **zod** into this lazily-loaded game chunk, for five lines of loop. Room shapes stay structurally identical to floor-plan's `Rect` so "walk a real plan" stays a small adapter.
  - Canvas scales by **whole multiples only**. Pixel art at a fractional scale is worse with `image-rendering: pixelated`, not better — nearest-neighbour duplicates some source columns and not others, so strokes go uneven and the image shimmers.
  - **Scores get a table PER GAME** (`site_snap_scores`), not one generic `game_runs` keyed by slug. Asked and answered on 2026-09-08: a generic append-only table was proposed — one migration ever, one shared API route and leaderboard, plus full run history for checking the balance against real players — and was declined in favour of per-game typed columns and constraints. So each new game costs its own migration (hand-pasted while the token is expired), its own API route and its own leaderboard. Don't re-propose the merge without a reason that has changed.
  - Sprites are string-array pixel maps baked once into offscreen canvases (`sprites.ts`). `ctx.imageSmoothingEnabled` matters only for those `drawImage` calls — it does nothing for the `fillRect` work that draws the house.
